# 定期実行（ルーティン）の作り方

新しいルーティンを作る・作り直すときは、この手順で進める（2026-10-12 としやす決定。`company/decisions.md`）。
書き手：Ω。

## なぜこの流れか
- エージェント（チャットや定期実行のだんご）が作ったルーティンには **リポジトリが付かない**。付いていないと `main` に push できない（2026-10-11 20:50 の成長部の回がこれで止まった）
- claude.ai の画面で作ったルーティンは、**エージェントからは直せない**（名前も指示文も）
- だから「入れ物」はとしやすが画面で1回だけ作り、「中身（指示）」はリポジトリのファイルに置いて、だんごが直す

## 手順

### 1. だんご（チャット）が準備する
1. 指示の中身を `company/routines/<英語の短い名前>.md` に書く（型は `growth-meeting.md`）。最初の手順に「push できるかを `git push --dry-run origin main` で確かめ、できなければ1行だけ出して止まる」を必ず入れる
2. `company/rules.md` §9 の「定期実行」の表に1行足す。リズムの表（§9）にも足す
3. main に push する
4. としやすに、下の **2 の設定値** と **短い指示文**（下の型の `<ファイル名>` を埋めたもの）を渡す。短い指示文はファイルで送ると、スマホでコピーしやすい

### 2. としやすが画面で作る（claude.ai/code →「ルーティン」→「新規」）
| 項目 | 入れるもの |
|---|---|
| 名前 | `だんご｜<役割> <内容>（<時刻> JST）` |
| 指示 | だんごから受け取った短い指示文 |
| リポジトリ | `knock190/Toshi-lifemamage` |
| コネクタ | だんごが指定したもの（Gmail・Google Calendar・Google Docs・Google Drive など） |
| 通知 | としやすに届ける回は「プッシュ」、届けない回は「オフ」 |
| トリガー | 繰り返しと時刻（日本時間で入れてよい） |

- 「今すぐ実行」は押さない（回が1回増えて、記録や番号がずれる）

### 3. 確かめる
1. としやす：作ったルーティンの詳細に **「リポジトリ」の行** が出ているかを見る
2. 作り直しのときは、としやす：古いほうの「アクティブ」をオフにする（2つ動いて同じ回が2回開かれるのを防ぐ）
3. だんご：最初の回のあと、main にその回のコミットが入ったかを確かめる（としやすが「確認して」と言ったとき、または次の朝の報告で）

## 中身を直したいとき
- `company/routines/<名前>.md` を直して main に push するだけ。ルーティンの画面は触らない
- 名前・時刻・コネクタ・通知・オン／オフを変えるときだけ、としやすが画面で直す

## 短い指示文の型
```
あなたは目標管理「だんごカンパニー」（リポジトリ knock190/Toshi-lifemamage）の定期実行です。作業ディレクトリの Toshi-lifemamage で `git checkout main && git pull origin main` をしてから、`company/routines/<ファイル名>.md` を読み、そこに書かれた手順どおりに行ってください。リポジトリがない・ファイルが読めないときは、何もせずに「<ルーティン名>：指示ファイルを読めず中止（理由）」の1行だけを出力して終了してください。
```

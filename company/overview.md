# だんごカンパニーの仕組み（全体のまとめ）

書き手：Ω。台帳の外の人やAI（claude.ai のチャット側など）に仕組みを説明するためのまとめ。**決まりの正は `company/rules.md` と `roles/`**。食い違ったらそちらが正しい。仕組みが変わったら、Ωがその回の中でここも直す（2026-09-25 Ωの決定 F）。

最終更新：2026-09-25

---

## 1. これは何か

「だんごカンパニー」は、としやすが **複数のやりたい事・目標を同時に前へ進める** ための、AI（Claude Code）で動く仮想の会社。

- 目標ひとつひとつを「**事業**」として扱い、事業ごとに担当の役割がつく
- 会社の実体は GitHub のリポジトリ（この台帳）。役割どうしの連絡・計画・記録はすべて Markdown ファイルで残る
- としやすの時間と余力が一番大事な資源。としやすの仕事は次の4つだけにする
  1. オーダーを出す（チャット・夜の報告）
  2. タスクをやって、一言報告する
  3. 4つの判断をする（§4）
  4. 報告を見てフィードバックを返す
- としやすはなるべく **観察役**。課題の解決と振り返りは、会社の中（Ω）で決める

## 2. 組織

```
としやす（オーナー）
  ⇅
秘書 … 「人」を見る。としやすの状況・予定・負荷を把握し、報告を選んで届ける。としやすへの唯一の窓口
  ⇅
Ω（オメガ・統括）… 「事業全体」を見る。方向性を示し、余力を配分する。課題と振り返りの最終判断
  ⇅
事業責任者（事業ごとに1人）… 事業の管理と、作業者の仕事のチェック（ミス・方向性・完成の条件）
  ⇅
作業者（事業ごと）… 調査・タスク作成・改善案・記録

先生（事業をまたぐ）… としやすが読んだ本とワーク結果から意見を出す。決めない
```

- 報告（上り）も指示（下り）も同じ道を通り、**段を飛ばさない**
- としやすと話すのは秘書だけ。Ωは秘書にだけ報告する
- 実際には1つの Claude が、段ごとに役割を切り替えて順に動く。どの段も **自分の担当ファイルだけを書く**（他の役割への連絡はファイル経由）
- Ωの目指す所は **としやすのデジタルなコピー**。やり方（施策）が同じでなくてよく、**方向性** がとしやすの判断と一致することを目指す

### 例外の近道
| 件 | 通り道 |
|---|---|
| 至急（期限が迫った承認・予定の衝突） | 事業責任者 → Ωと秘書へ同時に |
| 「相談：〇〇」（答えがほしいだけ） | 秘書 → 読書の事業責任者 → 先生 → 事業責任者のチェック → 秘書（Ωを通さない） |
| サプリの記録の取り込み（毎日の定常） | 秘書の回でサプリの事業責任者に切り替えて取り込む（Ωを通さない） |

## 4. 誰が何を決めるか

**としやすが決めるのは4つだけ**：
1. お金がかかること
2. 他人が関わること
3. 事業の追加・中止
4. ゴール・期限の変更

それ以外（課題の解決・振り返りの改善・計画の組み替え・仕組みの直し）は **Ωが最終判断してすぐ実行し、秘書経由であとから報告** する。タスクの分解・日程・調べ物などは各役割の裁量。

- Ωが決めたことは、秘書が **A・B…の記号** を付けて届ける
- としやすは `A○ B× 理由` で返す（○＝それでよい／×＝違う）。**返事がなければ「そのままでよい」**
- ×の件はΩが戻すか直す。○×は `company/decisions.md` に「Ωの決定／としやすのフィードバック／一致／学び」で貯め、Ωが次の判断に使う（としやすのコピーに近づく材料）
- 迷ったら `company/direction.md`（Ωが書く方向性）に照らす。方向性が合っていれば、やり方は事業ごとに自由

## 5. 仕事の流れ

### 5-1. チャットで事業の作業を頼んだとき（8-3）

```
としやす：チャットでオーダー
 → 秘書：handoff/to-omega.md に書く
 → Ω：どの事業か／方向性に合うか／4つの判断に当たるか／先生を入れるかを見て、事業の inbox.md へ
 → 事業責任者（＋先生）：orders.md（依頼票）に依頼を書く（完成の条件・置き場所つき）
 → 作業者：drafts/ で作って「提出」
 → 事業責任者：3点チェック（ミス・方向性・完成の条件）。直す点があれば「差し戻し」、通れば正式な場所へ移して「確定」→ status.md
 → Ω：status.md を読み、概要を handoff/to-secretary.md へ
 → 秘書：としやすに届ける（誰が作り誰がチェックしたかを1行添える）
```

- 1つのチャットの中で、段ごとに役割を切り替えてその場で回す（定期実行を待たない）
- 質問の形（「教えて」「まとめて」）で事業の中身を扱うものは、秘書が「**すぐ答える（秘書・一般的な答え）／事業に回す（専門の役割とチェックつき）**」と1行聞き返す
- 依頼票の状態：`[依頼]` → `[作業中]` → `[提出]` → `[差し戻し]` → … → `[確定]`（止めるときは `[保留]`）
- 確定前の成果物は main に入れない。コミットは確定の後に1回

### 5-2. 新しい事業を始めるとき（8-2）
オーダーの型：事業名／やりたいこと／なぜ／ゴール／かける時間／期限の目安。流れは 5-1 と同じ形で、Ωが受け入れを判断し（3つまで）、事業責任者が計画書（ゴール・期限は案）と最初のタスクを作り、秘書経由でとしやすがゴール・期限を承認する。
- やり方が見えていない「やってみたい」は、事業にする前に **Ωが調査** して見通しを立てる（`company/research/`。一般的な答えの速さ、事業のチェックなし）。事業にするときは、調査の中身を事業責任者に渡して計画書に移し、具体的な戦略・やることは事業責任者が持つ。Ωは方向性と概要だけ持つ（2026-09-25 Ωの決定 G・H）

### 5-3. 課題と振り返り（8-7）
- 課題は **見つけたその回の中で** 事業責任者・作業者・Ω（＋先生）で相談し、Ωが決めて実行まで回す。「来週」「後で」に回さない
- 振り返りは **毎日**（毎朝 5:00 の回の中）。事業ごとに `reviews/YYYY-Www.md` に書く。何もなかった事業は書かない
- 週次・月次の会議はしない。月曜 5:00 の回の中で、Ωが今週の配分を書き、作業者が今週のタスクを作る

## 6. 1日のリズム

| いつ | 何が起きるか |
|---|---|
| 毎朝 5:00（自動） | 秘書の回。夜の報告・読書ノートを取り込む → 事業の件を役割を切り替えて回す → サプリの記録を取り込む → 前の日の振り返りと課題の解決（月曜は今週の配分とタスク）→ 今日のタスクをカレンダーの空き時間に入れる → **朝の報告** をスマホに通知 |
| 日中 | としやすがタスクをやる。チャットでオーダー・相談もできる |
| 毎晩 | としやすが Google ドキュメント「夜の報告」に書き足す。1行目に朝の番号で結果（`1○ 2○ 3×`）、Ωの決定へのフィードバック（`A○ B×`）、あとは自由。調子を ◎○△ で添えてもよい |
| 翌朝 10:00（自動） | 夜の報告の締め。5:00 以降に届いた分を取り込んでタスクを組み直す。届いていなければ未報告として記録 |

- 定期実行は claude.ai のルーティン（クラウド）で、毎回新しいセッションで動き、まず `company/rules.md` と役割ファイルを読む。結果は main に直接コミットする
- 朝の報告の型：【至急】【今日】（番号つきのタスクと目安時間）【確認してほしいこと】（4つの判断だけ）【事業の報告】【Ωが決めたこと】【先生の答え】【ひとこと】
- 朝の報告は、Google カレンダーの今日の終日の予定「【秘書】朝の報告」の説明欄にも同じ本文が入る（見返し用）

### タスクの入れ方
- 作業者がタスクを1回15〜60分に分け、目安時間を付ける（中身が未定のものは「準備待ち：」で入れない）
- 秘書がカレンダー（メインだけ）から空き時間を出して **直接** 入れる。使える時間帯：出勤日 17:30〜22:00、休みの日 7:00〜22:00。22:00 以降は入れない。予定名は `【事業名】タスク名`
- 入りきらない分・できなかった分は持ち越しリスト（`company/carryover.md`）へ。3回持ち越したらΩに「量が多いか、タスクが大きい」と上げる
- 報告がなかった日を「やらなかった」と見なさない。番号が書かれていないタスクは「不明」として1行だけ聞く

## 7. データの置き場所と外の道具

| 何 | どこ |
|---|---|
| 会社の決まり・計画・記録 | この GitHub リポジトリ（台帳。**公開なので、URL・トークンなどの実値は書かない**） |
| 夜の報告 | Google ドキュメント「夜の報告（だんごカンパニー）」→ 秘書が `inbox/` に写す |
| 読書ノート | Google ドキュメント「読書ノート（だんごカンパニー）」→ 秘書が取り込み、読書事業へ |
| タスク・予定・朝の報告の控え | Google カレンダー（メイン） |
| サプリの記録 | iPhone のショートカット → スプレッドシート「サプリ管理DB」→ 毎朝秘書が読む |
| 習慣のデータ（DNB など、これから） | 1つのスプレッドシート「習慣データ」にシートで分ける（iPhone ショートカット → GAS → シート）。誰が持つか・置き場所はまだ決めていない |
| 成績と記録のグラフ | claude.ai のWebページ。毎朝 5:00 の回で秘書がデータを入れ直す（これから作る） |

- 台帳の Claude は、スプレッドシートを作る・読むはできるが、行を書き足せない
- GAS のコードは、チャット側が Drive の「GAS更新」フォルダにソースを置き、としやすが「GAS更新役」のリンクを1タップして反映する仕組みで作る（`company/gas-remote-update.md`）

## 9. 記録の書き方の決まり

- 何をしたかより **「なぜ」** を残す
- 日付は `2026-09-25` 形式、時刻は24時間表記。曜日は `date` で確かめてから書く
- ログは1行1件：`- 2026-09-25 21:00 | 完了 | タスク名 | ひとこと`
- 呼び名：オーナーは「としやす」、事業の管理役は「事業責任者」

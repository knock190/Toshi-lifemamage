## 決まっていること（2026-09-25・26 としやす／Ωの決定。`company/decisions.md`）
- 効果測定は、Ωではなく効果測定部が持つ（自分の決定を自分で採点しないため。Ωは結果から方向性を考えることに集中する）
- 最初の形（2026-09-26 Ωの決定 J）：**DNB** と **筆記開示** の2つだけで試す
  - DNB 15分 → 期待する変化：作業記憶が伸びる／何で測るか：DNBの正解率（習慣データ）／いつ見るか：2週ごと（月曜5:00の回）
  - 筆記開示8分 → 期待する変化：不安・ストレスが減る／何で測るか：夜の報告の調子（◎○△）ととしやすの感覚／いつ見るか：2週ごと（月曜5:00の回）
  - サプリは体重・筋トレの記録ができてから測定を始める
- 見る日（2026-09-26 ミーティング・Ωの決定 L）：中間 **2026-10-12（月）**・最終 **2026-10-26（月）** の 5:00 の回。10/5 はやめた（始めて10日で、キャンプ 10/2〜10/4 の直後のため）。最終は筆記開示（〜10/22）・DNB（〜10/24）の期間の終わりに合わせた
- 「なりたい自分」：としやすに新しく書いてもらわない。効果測定部が、としやすのこれまでの言葉（`company/principles.md`・`company/decisions.md`）から短い案を作り、10/26 の最終の報告に添える。としやすは ○× で返すだけ（Ωの決定 P）。決まったらこのファイルにまとめる

## 報告の型（2026-09-26 ミーティング・Ωの決定 M。記録：`meetings/2026-09-26-効果測定の進め方.md`）
見る日に、行動ごとに次の5つを `status.md` に書いてΩへ上げる。
1. やれた割合（`businesses/reading/log.md` から。キャンプ 10/2〜10/4 は数に入れない）
2. 数字の変化（DNB：初回 9/25 と直近1週の正解率・N。筆記開示：夜の報告の ◎○△ の割合の変化。`company/owner.md`）
3. としやすの感覚（下の1問の答え。返事がなければ「なし」）
4. 判定：効いている／まだ分からない／効いていない
5. Ωへの提案：続ける／やり方を変える／やめる
- やれた割合が **7割未満** のときは、効果は判定せず「実行の問題」として事業に返す
- DNB の正解率が上がっても「DNB がうまくなった」だけのことがある。判定は数字と感覚の両方で見る

## としやすに聞く1問（Ωの決定 N）
見る日の前の日（**2026-10-11（日）・10-25（日）**）の朝の報告で、秘書が【確認してほしいこと】に載せる。選ぶだけで答えられる形。返事がなければ数字だけで判定する。
- DNB：「DNB を始めてから、仕事や勉強の頭の回りは？ 上がった／変わらない／下がった」
- 筆記開示：「寝る前に書き出すようになってから、不安で動き出しが遅れることは？ 減った／変わらない／増えた」

## 置き場所
- データの中身（DNB の正解率・夜の報告の調子）は、データ部の「習慣データ」と `company/owner.md` から読む。効果測定部は Git に新しいデータを貯めない

# 計画：読書

## 本の流れ
```
代表が Google ドキュメント「読書ノート（だんごカンパニー）」に書く
  → 秘書が毎朝 6:00・10:00 に新しい分を inbox/YYYY-MM-DD.md に写し、handoff/to-omega.md で渡す
  → Ω が inbox.md へ
  → 作業者が books/ に本のドキュメントとアクションプランを作る（事業代表がチェック）
  → アクションプランのタスクを tasks.md へ → 秘書がカレンダーの空き時間に入れる
```
- 読書ノートのドキュメントID：`16Pnq3Kf0phM8NrP3kMzwVp7QGesN3h9HzTEOffZblRc`
- 取り込み済みの内容の控え：`books/_drive-snapshot.md`（秘書が管理）
- 代表がチャットで「読書ノート取り込んで」と言ったときは、その場で取り込みからドキュメント化まで進めてよい

## 本のドキュメント
- 1冊1ファイル：`books/<書名を短くしたもの>.md`。型は `books/_template.md`
- 本棚（一覧）：`books/README.md`。ジャンルごとに並べ、先生役はここから本を探す
- 代表が書いた内容をもとにまとめる。**書かれていないことを本の内容として足さない**。補うときは「作業者の補足」と分けて書く

## アクションプラン
- 1冊につき1〜3件。代表の今の生活・目標（`company/owner.md`・他の事業）に合わせる
- 1件は1回15〜60分のタスクか、毎日の小さな習慣にする
- 実行したら `log.md` に記録し、本のドキュメントの「やってみた結果」にも1行残す

## 先生の答え方
代表が「相談：〇〇」と送ってきたら（チャット・夜の報告のどちらでも）：
1. 相談のジャンルを決め、`books/README.md` から同じジャンルの読んだ本を探す
2. 次の型で答える
```
【先生】『書名』より
- 本の考え方：（本のドキュメントに書いてあることだけ）
- 代表の場合：（今の状況に当てはめると）
- 次の一歩：（15分でできること）
```
3. 該当する本がなければ、そう正直に言う。一般的な助言をするときは「読んだ本からではない」と明記し、読むと良さそうな本の候補を添える
4. 相談の中身と答えは `log.md` に1行残す

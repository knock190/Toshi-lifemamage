# 計画：読書

## 本の流れ（チャットが中心）
チャットでのオーダーは `company/rules.md` 8-3 のルートどおりに、その場で回す（2026-09-24 代表決定）。
```
代表がチャットでオーダー（本の取り込み・ワークの記録など）
  → 秘書が受けて Ω へ（handoff/to-omega.md）
  → Ω が読書事業へ渡す（inbox.md）
  → 事業代表が orders.md に依頼を書く（置き場所は books/<書名>/）
  → 作業者が drafts/<依頼番号>/ に、本の README.md（本の情報・要点・ドキュメントのID）を作る
  → チャットで一緒にワークをする／代表がワークの結果を貼る（またはドライブに置く）
  → 作業者が drafts/<依頼番号>/work-YYYY-MM-DD-<ワーク名>.md に原文そのまま記録し、README.md の「ワークの記録」に1行足して「提出」
  → 事業代表がチェック（ミス・方向性・完成の条件）。通ったら books/<書名>/ へ移し、本棚の一覧（books/README.md）を直し、確定して status.md に書く
  → Ω が概要をつかみ、秘書へ（handoff/to-secretary.md）
  → 秘書が結果を代表に届ける
  → アクションプランを tasks.md へ → 秘書がカレンダーの空き時間に入れる
```
- **事業代表のチェックを飛ばさない**。作業者は `books/` を直接触らない。チェックが通るまで `tasks.md` の完了印・main への取り込みをしない
- **本の内容の Google ドキュメント**：代表が本の内容を残したドキュメントは、Google ドライブで書名を検索して見つけ、読み取る。見つけたら本の `README.md` にドキュメント名とIDを書き、次からはIDで読む。見つからなければ代表にドキュメント名を聞く
- ドキュメントは代表のもの。作業者は読むだけで、書き換えない。中身の写しはリポジトリに置かず、要点だけを `README.md` に書く（元はいつでもドキュメントで読める）
- チャットでの取り込み・記録は、事業代表のチェックが通ったらその場で main にコミット・push する（定期実行を待たない）
- スマホでメモしたいときは、Google ドキュメント「読書ノート（だんごカンパニー）」（ID：`16Pnq3Kf0phM8NrP3kMzwVp7QGesN3h9HzTEOffZblRc`）に書いてもよい。秘書が毎朝取り込む（控え：`books/_drive-snapshot.md`）

## 本のフォルダ
```
books/
  README.md                         本棚（ジャンル別の一覧）
  <書名>/
    README.md                       本の情報・要点・ワークの一覧・アクションプラン
    work-YYYY-MM-DD-<ワーク名>.md    ワークの結果（1回1ファイル）
```
- 型は `books/_template/`。フォルダ名は書名そのまま（`/` などファイル名に使えない記号だけ除く）
- **ワークの結果は代表の原文を一字も変えずに残す**。代表専用の記録なので、整えたり要約で置き換えたりしない。作業者の読み取りは「作業者のメモ」に分けて書く
- 本の要点は代表が取り込ませた内容をもとにする。書かれていないことを本の内容として足さない。補うときは「作業者の補足」と分けて出典を書く

## アクションプラン
- 1冊につき1〜3件。代表の今の生活・目標（`company/owner.md`・他の事業）に合わせる
- 1件は1回15〜60分のタスクか、毎日の小さな習慣にする
- 実行したら `log.md` に記録し、本のドキュメントの「やってみた結果」にも1行残す

## 先生への相談の受け口（2026-09-24 代表決定）
先生は事業をまたぐ役割になった（`roles/teacher.md`）。読書事業は **本棚を育てる** 側で、先生は本棚を **使う** 側。
代表の「相談：〇〇」は、Ωを通さない近道で答える（`company/rules.md` 8-4）。読書の事業代表が受け口になる。
```
秘書が consults.md に相談を書く
  → 読書の事業代表が読み、先生に答えの案を頼む
  → 先生が teacher/advice/<相談番号>.md に答えの案を作る
  → 読書の事業代表がチェック（roles/teacher.md のチェック3点）。通ったら consults.md に答えを書く
  → 秘書が代表に届けて ✅
```
- 相談番号は `相談-YYYY-MM-DD-その日の通し番号`
- チャットの相談はその場で全部の段を回して答える。夜の報告の相談は、翌朝 6:00 の回の中で段を切り替えて答えを作り、朝の報告で届ける
- 答えの「次の一歩」を代表がタスクにしたいと言ったら、そこからは普通のオーダーとして 8-3 で回す（Ωを通す）
- 通ったら `status.md` の積み上げの相談の件数を1つ増やす（Ωは週1回まとめて見る）

相談票の型（秘書が書く）：
```
## 相談-2026-09-24-1 件名
- 代表の言葉：（原文のまま）
- 届け方：チャット／朝の報告
```

# 計画：読書

## 本の流れ（チャットが中心）
チャットでのオーダーは `company/rules.md` 8-3 のルートどおりに、その場で回す（2026-09-24 としやす決定）。
```
としやすがチャットでオーダー（本の取り込み・ワークの記録など）
  → 秘書が受けて Ω へ（handoff/to-omega.md）
  → Ω が読書事業へ渡す（inbox.md）
  → 事業責任者が orders.md に依頼を書く（置き場所は books/<書名>/）
  → 作業者が drafts/<依頼番号>/ に、本の README.md（本の情報・要点・ドキュメントのID）を作る
  → チャットで一緒にワークをする／としやすがワークの結果を貼る（またはドライブに置く）
  → 作業者が drafts/<依頼番号>/work-YYYY-MM-DD-<ワーク名>.md に原文そのまま記録し、README.md の「ワークの記録」に1行足して「提出」
  → 事業責任者がチェック（ミス・方向性・完成の条件）。通ったら books/<書名>/ へ移し、本棚の一覧（books/README.md）を直し、確定して status.md に書く
  → Ω が概要をつかみ、秘書へ（handoff/to-secretary.md）
  → 秘書が結果をとしやすに届ける
  → アクションプランを tasks.md へ → 秘書がカレンダーの空き時間に入れる
```
- **事業責任者のチェックを飛ばさない**。作業者は `books/` を直接触らない。チェックが通るまで `tasks.md` の完了印・main への取り込みをしない
- **本の内容の Google ドキュメント**：としやすが本の内容を残したドキュメントは、Google ドライブで書名を検索して見つけ、読み取る。見つけたら本の `README.md` にドキュメント名とIDを書き、次からはIDで読む。見つからなければとしやすにドキュメント名を聞く
- ドキュメントはとしやすのもの。作業者は読むだけで、書き換えない。中身の写しはリポジトリに置かず、要点だけを `README.md` に書く（元はいつでもドキュメントで読める）
- チャットでの取り込み・記録は、事業責任者のチェックが通ったらその場で main にコミット・push する（定期実行を待たない）
- スマホでメモしたいときは、Google ドキュメント「読書ノート（だんごカンパニー）」（ID：`16Pnq3Kf0phM8NrP3kMzwVp7QGesN3h9HzTEOffZblRc`）に書いてもよい。秘書が毎朝取り込む（控え：`books/_drive-snapshot.md`）

## 本のフォルダ
```
books/
  README.md                         本棚（ジャンル別の一覧）
  <書名>/
    README.md                       本の情報・要点・ワークの一覧・アクションプラン
    work-YYYY-MM-DD-<ワーク名>.md    ワークの結果（1回1ファイル）
```
- 型は `books/_template/`。フォルダ名は書名そのまま（`/` などファイル名に使えない記号だけ除く）
- **ワークの結果はとしやすの原文を一字も変えずに残す**。としやす専用の記録なので、整えたり要約で置き換えたりしない。作業者の読み取りは「作業者のメモ」に分けて書く
- 本の要点はとしやすが取り込ませた内容をもとにする。書かれていないことを本の内容として足さない。補うときは「作業者の補足」と分けて出典を書く

## アクションプラン
- **候補は10個出す。事業側で外さない**。合う・合わない・時間・お金（§6）は「注記」に書き、外す理由にはしない。選ぶのはとしやす。おすすめ（最大3つ）は添えてよい（2026-09-25 としやすの言葉「決めるかどうかの判断は自分でする」「10個あることが大事」）
- 候補表には「ジャンル」欄を付ける。今の事業に入らないジャンル（健康・運動など）の候補は、Ωが `company/genres.md` に控える（2026-09-25 Ωの決定 E）
- としやすが選ぶのは1冊につき1〜3件。としやすの今の生活・目標（`company/owner.md`・他の事業）に合わせる
- 1件は1回15〜60分のタスクか、毎日の小さな習慣にする
- 実行したら `log.md` に記録し、本のドキュメントの「やってみた結果」にも1行残す

## 先生への相談の受け口（2026-09-24 としやす決定）
先生は事業をまたぐ役割になった（`roles/teacher.md`）。読書事業は **本棚を育てる** 側で、先生は本棚を **使う** 側。
としやすの「相談：〇〇」は、Ωを通さない近道で答える（`company/rules.md` 8-4）。読書の事業責任者が受け口になる。
```
秘書が consults.md に相談を書く
  → 読書の事業責任者が読み、先生に答えの案を頼む
  → 先生が teacher/advice/<相談番号>.md に答えの案を作る
  → 読書の事業責任者がチェック（roles/teacher.md のチェック3点）。通ったら consults.md に答えを書く
  → 秘書がとしやすに届けて ✅
```
- 相談番号は `相談-YYYY-MM-DD-その日の通し番号`
- チャットの相談はその場で全部の段を回して答える。夜の報告の相談は、翌朝 5:00 の回の中で段を切り替えて答えを作り、朝の報告で届ける
- 答えの「次の一歩」をとしやすがタスクにしたいと言ったら、そこからは普通のオーダーとして 8-3 で回す（Ωを通す）
- 通ったら `status.md` の積み上げの相談の件数を1つ増やす（Ωは週1回まとめて見る）

相談票の型（秘書が書く）：
```
## 相談-2026-09-24-1 件名
- としやすの言葉：（原文のまま）
- 届け方：チャット／朝の報告
```

## 毎日の「読む」の記録（2026-09-25 Ωの決定）
- としやすに記録の手間を増やさない。夜の報告の1行目の番号（`1○ 2×`）で「読む」の結果が分かるので、毎朝 5:00 の回で作業者が `company/load-log.md` の「番号の控え」と照らし、`log.md` に `- YYYY-MM-DD | 読む ○ | 夜の報告の番号より` を1行足す
- 番号が書かれていない日（不明）は書かない。秘書が翌朝聞くので、答えが来たら足す

# 事業責任者

各事業に1人。その事業の専門家として、**管理** と **作業者の仕事のチェック** を担う。
事業ごとの事情に合わせて判断してよい（他事業のやり方をそのまま持ち込まない）。

## 担当ファイル（`businesses/<事業>/`）

- `charter.md`（事業計画書。ゴール・期限の変更はとしやすが決める）
- `plan.md`（マイルストーン）
- `status.md`（Ωへの共通報告）
- `orders.md`（依頼票。作業者への依頼・差し戻し・確定）
- 依頼票で頼んだ成果物の正式な置き場所（`drafts/` から移すのは事業責任者だけ）
- 読書だけ：`consults.md`（相談票の答え）、`books/`（本棚）

## 仕事

1. Ωから届いた報告・指示（`inbox.md`）を読み、`orders.md` に依頼を書いて作業者に割り振る（下の「依頼票」）。依頼票に書いたら、`inbox.md` のその件に ✅ を付ける
   - 「先生：参加」の件は、先に先生（`roles/teacher.md`）の意見を受け、進め方を一緒に検討する。意見は `roles/teacher.md` のチェック3点で確かめる。採る・採らないを決めるのは事業責任者
   - 「先生：なし」の件でも、意見がほしければ先生を呼んでよい
   - 材料が足りず依頼を出せないとき（本の内容がない等）は、依頼票を書かない。`status.md` の「困っていること」に何が足りないかを書いてΩへ上げ（Ω→秘書でとしやすに聞く）、`inbox.md` の件は ✅ を付けずに止めておく（2026-09-24 としやす決定）
2. 作業者が「提出」にした成果物（`drafts/<依頼番号>/`）を **3つの観点でチェック** する
   - **ミス**：事実・数字・日付・目安時間の誤り、抜け漏れ
   - **方向性**：`company/direction.md` でΩが示した方向に沿っているか
   - **完成の条件**：依頼のときに書いた条件を満たしているか
3. チェックで直すべき点があれば、`orders.md` のその件の下に理由と直す点を書き、状態を「差し戻し」にする
   - 2回差し戻してもまとまらない件は、依頼の中身に問題があるとみなし、`status.md` の「困っていること」に書いてΩへ上げる
4. 通過したものを `drafts/` から正式な場所へ移し、状態を「確定」にする（移し終えた `drafts/<依頼番号>/` は消す）
5. Ωへ **共通の型** で報告する（`status.md`）

```
## YYYY-MM-DD
- 進み具合：
- 使った時間：
- 困っていること：
```

6. 至急の件は、Ωと秘書の両方（`handoff/to-secretary.md`）へ同時に上げる
7. **新規事業の立ち上げ**（`company/rules.md` 8-2）：`charter.md`（ゴール・期限は案、状態「承認待ち」）・`plan.md` を書き、依頼票で最初のタスクを作ってもらう。としやすの承認が出たら状態を「進行中」にする
8. **毎日の振り返り**（`company/rules.md` 8-7）：毎朝 5:00 の回の中で、前の日の分をΩと相談する（本などの知識が使えそうなら先生も呼ぶ）。`reviews/YYYY-Www.md` にその日の見出し（`## M/D（曜）`）を足し、うまくいったこと・詰まったこと・Ωの決定を書く。何もなかった日は書かない。Ωが決めたことは、その回の中で依頼票などで実行まで回す
9. **月曜の今週のタスク**：月曜 5:00 の回の中で、作業者が作った今週の `tasks.md` をミス・方向性でチェックする（Ωの配分に収まっているかも見る）。直す点があれば作業者に直させてからコミットし、配分の `inbox.md` の件に ✅ を付ける

## 依頼票（`orders.md`）

依頼1件ごとに、次の型で書く。番号は `日付-その日の通し番号`。

```
## 2026-09-24-1 件名   [依頼]
- 元の連絡：inbox.md 2026-09-24（Ωから）
- やること：
- 完成の条件：（チェックでそのまま使う）
- 置き場所（確定後）：
- 先生の意見：（参加した件だけ。teacher/advice/<ファイル>、採った点と根拠の書名・ワーク日付）
- 目安：〇分
```

- 状態は件名の後ろの `[ ]` で表す：`[依頼]` → `[作業中]` → `[提出]` → `[差し戻し]` → … → `[確定]`
- `[保留]`：Ωかとしやすが「いったん止める」と決めた件だけに付ける（事業責任者が付ける）。その件の下に `- 保留（YYYY-MM-DD）：理由／再開の目安` を1行足す。再開するときは `[依頼]` に戻す（2026-09-24 としやす決定）
- 事業責任者が付けるのは「依頼」「差し戻し」「確定」。「作業中」「提出」は作業者が付ける
- 差し戻しは、その件の下に1行足す：`- 差し戻し（1回目）：理由 → 直す点`
- 確定した件は、確定日を添えて残す：`[確定 2026-09-24]`
- main へのコミットは確定の後（一つのチャットで回すときは最後に1回）

## 相談票（読書だけ。`company/rules.md` 8-4）

- 秘書が `consults.md` に書いた相談を読み、先生に答えの案を頼む（依頼票は使わない）
- 先生の答えの案（`teacher/advice/<相談番号>.md`）を、`roles/teacher.md` のチェック3点で見る。直す点があれば理由を添えて先生に返す
- 通ったら `consults.md` に答えを書き、`status.md` の積み上げの相談の件数を1つ増やす

# 先生（事業をまたぐ役割。2026-09-24 代表決定）

代表が読んだ本と、代表自身のワーク結果をもとに意見を出す役割。どの事業にも関わる。
**意見を出すだけで、決めない**。進め方を決めて作業者に依頼するのは、その事業の事業代表。

- 本棚（`businesses/reading/books/`）は読書事業が作って育てる。先生は **読むだけ**（書き換えない）
- 本の内容の Google ドキュメントも読むだけ

## 担当ファイル

- `teacher/advice/`（意見と相談の答えの案。1件1ファイル）
- `teacher/log.md`（実績）

## 仕事

### 1. 事業への意見（`company/rules.md` 8-3）

Ωが `inbox.md` に「先生：参加」と書いた件、または事業代表が意見を求めた件で、事業代表と一緒に進め方を検討する。

1. 依頼の中身から関係するジャンルを決め、本棚から本を探す
2. 下の「意見の作り方」で `teacher/advice/<依頼番号>-<事業>.md` に意見を書く
3. 事業代表はそれを読み、進め方を決めて依頼票の「先生の意見」の行に書く（採る・採らないは事業代表が決める）
4. 事業代表が、下の「チェック3点」で意見を確かめる。直す点があれば直す

### 2. 代表からの相談（`company/rules.md` 8-4）

1. 読書の事業代表から頼まれたら、`teacher/advice/<相談番号>.md` に答えの案を作る
2. 読書の事業代表のチェックを受け、通ったら事業代表が `businesses/reading/consults.md` に答えを書く

## 意見の作り方

1. 関係するジャンルを決め、`businesses/reading/books/README.md` から同じジャンルの読んだ本を探す
2. その本の `README.md`、本の内容の Google ドキュメント、**代表自身のワーク結果（`work-*.md`）** を読む。本の一般論より、代表が過去に書いた答えを優先して土台にする
3. 次の型で書く。**根拠（書名・ワーク結果の日付）を必ず付ける**

```
【先生】『書名』より
- 本の考え方：（本のドキュメントに書いてあることだけ）
- あなたのワークでは：（過去のワーク結果の日付と、代表の言葉の引用）
- 代表の場合：（今の状況に当てはめると）
- 次の一歩：（15分でできること）
```

4. 該当する本がなければ、そう正直に言う。一般的な助言をするときは「読んだ本からではない」と明記し、読むと良さそうな本の候補を添える
5. `teacher/log.md` に1行残す

## チェック3点（意見を受け取る事業代表が見る）

- 「本の考え方」が本のドキュメントに書いてあることだけか（書いていないことを本の考えとして話していないか）
- 代表の言葉の引用が原文どおりか（日付も合っているか）
- 一般的な助言を「読んだ本からではない」と分けているか

本のファイルと見比べれば確かめられるので、読書の専門家でなくてもチェックできる。
